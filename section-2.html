Section 2 · Project Definition

Project Definition

Purpose of this section: define the project's persona, system prompt, and target exemplar before any generation or conversion takes place.

2.1 Why the Project Definition Comes First

Every downstream stage in the Studio — synthetic batch generation, document-to-SFT conversion, optional TRiAD alignment, and quality assurance — operates against the project definition established here. Downstream screens display a "Locked Project" status to confirm that they are working from this definition rather than inviting redefinition at each stage.

2.2 The Definition Fields

Input

Persona / target description

Describes who or what the model should become: the character, role, or behavioral target the SFT examples will steer toward. The supplied material references named personas in the active project — for example, the "Socrates (Athenian Sage)" project shown in the exported screenshots.

Input

System prompt definition

The standing instruction injected into training examples so the fine-tuned model inherits the project's behavioral frame. TRiAD alignment (Section 5) explicitly describes injecting the project-specific system prompt into pre-generated examples before import, which confirms the system prompt is treated as project-level data.

Input

Target exemplar

A reference example of the ideal training item. The support conversation shown in Section 11 demonstrates that the Studio can coach reviewers on what makes a good target exemplar relative to the current persona — the definition is meant to be concrete, not abstract.

State

Lock status

Once the project is established, downstream stages expose a "Locked Project" indicator — seen, for example, on the Document-to-SFT screen covered in Section 4. The supplied documentation does not document a separate unlock action on those downstream screens, so this manual does not infer one.

2.3 Locked Project Status on Downstream Screens

The "Locked Project" indicator is the mechanism by which later stages reference this definition. The conversion screen (Section 4) shows it explicitly, and the generation and alignment stages operate on the same principle: the definition is an input, not an editable field, at those stages.

Operating rule

Treat the project definition as the contract for everything produced afterward. Changing persona, system prompt, or exemplar after material has been generated invalidates the assumptions earlier batches were built on. The supplied documentation does not describe automated propagation of definition changes into existing batches.
