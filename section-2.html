Section 2 · Project Definition

Project Definition

Purpose of this section: define the persona, system prompt, and target exemplar that anchor every later generation, conversion, alignment, and quality-assurance stage.

2.1 The Project Definition Comes First

The supplied documentation establishes the project definition as the anchor for the entire pipeline. Downstream screens — document conversion (Section 4), TRiAD alignment (Section 5), and quality assurance — display a "Locked Project" status rather than inviting you to redefine the project at each stage.

2.2 Persona, System Prompt, and Target Exemplar

Input

Persona

The named identity the dataset should teach — a character, role, or behavioral target. The supplied screenshots show projects defined around personas such as "Socrates (Athenian Sage)."

Input

System prompt

The project-level instruction injected into training examples. TRiAD alignment (Section 5) explicitly describes injecting the project-specific system prompt into pre-generated examples before import, which confirms the system prompt is treated as project-level data.

Input

Target exemplar

A concrete model of the ideal training example. The App Support conversation shown in Section 11 demonstrates that the Studio answers questions like "How should I write a good example for the target exemplar?" against the current project definition — the exemplar defines the target structure, not just a vague aspiration.

State

Locked Project

The indicator shown on downstream screens — visible, for example, on the Document-to-SFT converter covered in Section 4. The source does not document a separate unlock action on those downstream screens, so this manual does not infer one.

2.3 Locked Project Status Downstream

The "Locked Project" indicator is the mechanism by which later stages reference this definition: the definition is an input, not an editable field, on the conversion and alignment screens.

Operating rule

Treat the project definition as the contract for everything produced afterward. The supplied documentation does not describe automated propagation of definition changes into existing batches.
