Section 7 · Image & Data Registry

Image & Data Registry

Purpose of this section: select QA-checked registry batches for inclusion in the final dataset, and hand that selection to Compile.

7.1 What the Registry Holds

The registry is the inventory of batches produced by synthetic generation (Section 3), document conversion (Section 4), and any pre-generated imports such as TRiAD alignment (Section 5). Each batch carries provenance — an ID, a type, and a date — the same provenance surfaced on the batch card used by the AI Quality Assessor.

The registry screen states its purpose directly: "Dataset Registry — Select QA-checked batches to include in the final dataset."

7.2 Selection and the QA Gate

Selection is the registry's core action: only QA-checked batches should be included. The AI Quality Assessor (Section 6) provides the audit evidence; approval there gates inclusion here.

Selection

Select QA-checked batches

Choose which registry batches feed the compiled dataset. The supplied documentation does not describe list sorting, filtering, or bulk-selection behaviors, so none are asserted here.

State

Batch-count badge

The workflow navigation's registry item displays a badge noting how many batches exist. The supplied documentation does not specify whether the badge counts all batches or only selected ones; treat it as an existence counter.

7.3 Handoff to Compile

Once the selection is right, proceed to Compile (Section 8), which combines the registry's selected batches into one working dataset with an automatic validation partition. If the compile screen's batch count or totals look wrong, return here and correct the selection — Section 8's "What to Check" guidance says exactly this.

Note

The supplied pages do not document registry editing, renaming, or deletion mechanics. This manual does not infer them.
