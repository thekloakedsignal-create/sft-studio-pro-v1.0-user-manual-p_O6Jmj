Section 3 · Synthetic SFT Batch Generator

Synthetic SFT Batch Generator

Purpose of this section: generate synthetic SFT training batches from the locked project definition, producing candidate examples that flow into the Dataset Registry for QA review (Sections 6–7) before compile.

3.1 Batch Generation Concept

The generator produces synthetic SFT examples in batches rather than one item at a time. A batch is the unit the rest of the pipeline understands: it is registered in the Dataset Registry (Section 7), audited by the AI Quality Assessor (Section 6), and ultimately selected for compile (Section 8).

Generation draws on the locked project definition documented in Section 2 — persona, system prompt, and target exemplar — so each candidate example inherits the project's behavioral frame.

3.2 Generated Material Is Candidate Data

The Studio treats generator output as candidate data pending human review. Nothing produced at this stage is final: the batch is audited by the AI Quality Assessor, and only QA-checked batches are eligible for inclusion in the compiled dataset.

Operating rule

Do not route generated material straight to export. The pipeline is deliberately staged: generate → audit → select → compile → format → export.

3.3 Relationship to the Registry

Every generated batch enters the Dataset Registry with provenance information — an ID, a type, and a date — the same provenance surfaced on the batch card used by the AI Quality Assessor. The registry's batch-count badge on the workflow navigation reflects how many batches currently exist.

The supplied documentation does not specify the generator's prompt controls, sampling parameters, or batch-size options for this stage. Those mechanics are not described in the source material, and they are not invented here.
