Section 6 · AI Quality Assessor

AI Quality Assessor

Purpose of this section: a button-by-button guide to auditing batches, interpreting QA flags, repairing defective examples, and deciding when a batch is ready to approve.

6.1 What the AI Quality Assessor Does

The AI Quality Assessor is the Studio's batch-level quality checkpoint. It evaluates every example in a selected registry batch and looks for problems that can be difficult to catch by hand across a larger dataset. The source documentation identifies checks for full-format validity, template consistency, schema structure, persona/target consistency, and other indicators of corrupted or drifting examples.

The assessor produces a batch-level audit score and reports how many examples passed and how many were flagged. A flag is accompanied by an explanation so the reviewer can inspect the actual problem instead of treating the score as an unexplained red number.

Operating rule

QA is diagnostic, not sovereign. The documentation explicitly leaves the final decision to the human reviewer. A flagged example may be edited, rejected, or retained when the reviewer determines that the warning is not material.

6.2 Select the Batch to Audit

The AI Quality Assessor begins with the ACTIVE REGISTRY BATCH selector. The assessor works against a batch that is already in the registry, rather than auditing an arbitrary text field or an untracked draft.

Selection

ACTIVE REGISTRY BATCH

Use this selector to choose the registry batch that the assessor should evaluate. The screenshot shows a selected batch displayed in a purple dropdown-style control. The source documentation does not specify additional filtering behavior, keyboard shortcuts, or sorting rules for this selector, so those behaviors are not asserted here.

State

Audit Score: N/A / Needs Analysis

Before an audit has been run for the selected batch, the score area can display N/A with the status Needs Analysis. This means the batch has not yet received the audit result represented by the score display.

The batch card below the score identifies the selected batch and exposes provenance information such as its ID, type, and date. The copy icon shown beside the ID is visible in the interface, but the supplied documentation does not explicitly describe its action. Treat it as an interface control whose exact behavior is not documented here rather than assigning it an undocumented purpose.

6.3 Understanding the Audit Result

The completed audit presents a percentage score together with a pass/fail status. The documented example shows an 89% audit score with the status Passed Quality Audit, a passed count of 4, flagged items 1, and redundant entries 0. Read the score together with the counts: a batch can pass overall while still containing flagged items that deserve individual attention.

6.4 Acting on the Result

The documentation for this stage covers three remedies once an audit completes: regenerating flagged items, deduplicating redundant entries, and approving or rejecting the batch. These map directly onto the three counts the audit reports.

Action

Regenerate flagged items

Repair path for examples the audit flagged. Use regeneration to replace defective examples rather than shipping them. The fine-grained regeneration mechanics are not described in the supplied material, so none are asserted here.

Action

Deduplicate redundant entries

The audit counts redundant entries separately from flagged items; the documented example shows redundant entries 0. Where redundancy is found, deduplication removes it before the batch is approved.

Action

Approve / Reject

The final human decision on the batch. Approval makes the batch eligible for selection in the Dataset Registry (Section 7); the callout in Section 6.1 applies — the reviewer decides, the score only informs.
